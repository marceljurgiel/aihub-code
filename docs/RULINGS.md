# Design rulings

The harness was built in stages inside AIhub and moved here unchanged. Code comments refer to these rulings (R13, R33, ...) where a behaviour was a deliberate decision. Each line ends with the cost if the decision turns out wrong.

- Ruling R1: drop the spec's `code_mode` event; `code.mode` returns the mode — oneshot calls can't stream events — cost if wrong: one trivial event added in the interactive UI.
- Ruling R2: aihub_code/tools.py imports `schemas_for_agent` and `run_tool`, `run_shell` at module level so tests patch `aihub_code.tools.*` — cost if wrong: slower import of mcp_client (lazy import fix).
- Ruling R3: work on local branch `code-harness`, never main; merging/pushing needs the user's OK — cost if wrong: none (fast-forward later).
- Ruling R4: MCP/KB opt-in per code session (spec said "as in agents") — keeps small models at 7 tools — cost if wrong: interactive UI must offer toggles.
- Ruling R5: plan mode + write outside root/.git → deny(PLAN_DENIAL) instead of ask — spec: plan is read-only, stricter is safe — cost if wrong: none for users (plan can't write anyway).
- Ruling R6: dangerous command in build without exact rule → ask with suggested_rule = exact command — a prefix rule could never satisfy rule 5 — cost if wrong: UI shows a long suggested rule.
- Ruling R7: split_command returns None (no rule matching) for a lone `&`, `(`, `)` on POSIX; on Windows also for `\n`, `\r`, `(`, `)`, `{`, `}`, `@`, `$` — plan's separator list was incomplete; spec intent "every segment must match" — cost if wrong: more prompts for exotic commands.
- Ruling R8: any path component equal to ".git" (case-insensitive, every OS) is protected like the root .git (covers nested repos/submodules, macOS case) — cost if wrong: editing a file literally inside a nested .git needs approval.
- Ruling R9: dangerous detection = existing substring check PLUS per-segment unquoted first-token set (rm, rmdir, dd, mkfs*, shred, fdisk, parted, truncate, Remove-Item, ri, del, erase, rd, Format-Volume, Clear-Disk) and `find … -delete`, `git clean`, pipe into sh/bash/zsh/pwsh/powershell → ask even in auto; auto is still not a sandbox (docs must say so in stage 4) — cost if wrong: more prompts in auto.
- Ruling R10: suggest_rule returns the exact command when the first token is an interpreter/wrapper (python, python3, node, deno, ruby, perl, php, bash, sh, zsh, fish, pwsh, powershell, cmd, env, sudo, doas, xargs, nohup, time, exec, eval, npx, bunx, uvx, pipx) or for `git push|reset|clean|checkout|rebase` — cost if wrong: narrower always-allow rules.
- Ruling R11: in decide(), non-str name → ask; a "__" name that split_name can't parse (unknown MCP server) → ask, not allow — cost if wrong: none.
- Ruling R12: suggest_rule gives a prefix rule only for a bare program name (^[A-Za-z0-9_][A-Za-z0-9_.+-]*$, not a runner/wrapper, not risky git, not bun x/npx/bunx); otherwise exact command — fail-closed, simpler than enumerating — cost if wrong: narrower suggestions, more prompts.
- Ruling R13: make the real tool byte-preserving now (Review Focus 4): one shared pure function in aihub_code/engine/file_ops.py (`apply_edit(content, old, new) -> tuple[str|None, str|None]`, CRLF-aware: LF `old`/`new` converted to CRLF when the file uses CRLF and plain match fails) used by both edit_file and diffs.preview; edit_file reads bytes, decodes utf-8 else latin-1, writes back in the same encoding with no newline translation; write_file writes with newline="" (no translation) — a copy owned by aihub-code (AIhub 1.5.0's tools are untouched), and CodeToolRunner routes edit_file/write_file only here, so the preview equals the write — cost if wrong: Windows write_file now keeps LF as given instead of converting to CRLF.
- Ruling R14: accept commit-tree (parentless commits held only by refs/aihub/<turn>/*) instead of commit --allow-empty + HEAD — pruning frees space — and diff-tree -r -z --no-renames instead of diff --name-status — no rename detection, raw modes skip gitlinks — cost if wrong: none functional.
- Ruling R15: new public CheckpointError (undo can't be computed/applied; turn not marked undone) — the caller must catch it and surface the message.
- Ruling R16: undo is TURN-SCOPED: restore/delete only paths in diff(start,end); conflicts = those paths ∩ diff(end,now); paths changed only after the turn are left alone. When end is missing or finished=False → plan start→now with EVERY path a conflict (force required). Overrides spec/plan "diff start now" — cost if wrong: a later user change to a turn-touched path still needs force (intended).
- Ruling R17: UndoPlan gains `skipped: list[str]` (paths undo can't handle safely: symlinked parents, type changes it can't restore, unrecorded copies); never silently drop. a front-end must surface `skipped`.
- Ruling R18: shadow excludes also include the repo's own `<root>/.git/info/exclude` (read as a plain file when .git is a dir; appended to the shadow exclude). Project-as-subdir case doesn't occur via CodeSession (find_root returns the git top) — documented, not handled.
- Ruling R19: "fallback never crashes the turn" covers OSErrors in __init__/_init_shadow/_start_manifest (→ files mode or a no-op with note); swallowed _save_state/_write_manifest errors get a log.warning; non-dict state.json → treated as empty.
- Ruling R20: in-turn compaction — when the user-turn cut leaves nothing to compact (cut ≤ 1) or the kept part exceeds 40 % ctx, cut at a tool-round boundary inside the last turn: keep the latest rounds within 40 % ctx (min 1 round; start at an assistant tool_calls msg, never mid-pair); prune older tool results of that turn first; if still over → summarise the rounds between the turn's user request and the kept rounds; result layout [system, summary(user, SUMMARY_PREFIX), the turn's user request verbatim, kept rounds…] — the request is never summarised away — cost if wrong: one extra layout to maintain.
- Ruling R21: checkpoint turn ids are `<session.id>-<8 hex>` (unique; a popped turn number must never reuse the refs of an undone turn) kept in a parallel `turn_ids` list persisted in the session JSON — brief's `<id>-<n>` collides after undo — cost if wrong: none.
- Ruling R22: undo only undoes THIS session's last turn: `undo_plan().turn_id` must equal `turn_ids[-1]`, else CheckpointError("The last change on disk was made in another session; nothing was undone.") — one shadow store per project is shared by sessions — cost if wrong: a user must undo from the other session.
- Ruling R23: compaction keeps turn_starts valid by object identity: after any compaction, each turn start whose user message dict survived gets its new index, others become None; undo of a turn with start None restores files and appends {"role":"user","content":"[The user undid the file changes of that turn.]"} instead of truncating — cost if wrong: history keeps a summarised mention of an undone turn.
- Ruling R24: one running `aihub-code` turn per project across processes — the headless run and the bridge take an OS file lock `<store>/session.lock` (aihub_code/engine/filelock.py) for the duration of a turn/undo and fail fast with "Another aihub-code session is working in this project." — cross-process state.json is last-writer-wins otherwise — cost if wrong: a second concurrent run is refused (intended).
- Ruling R25: a files-mode turn without a manifest ("checkpoints are off") must not block undo forever: undo marks it undone and returns a plan with skipped=["(no checkpoint was taken for this turn)"] — cost if wrong: that turn's files aren't reverted (reported, not silent).
- Ruling R26: bridge code.* — (a) `chat.permission` consent only when params.allow is JSON true (`is True`), remember passed only when it's a str; (b) code.turn reuses _drive_turn's registry via a shared helper (no duplicated registry code); (c) R24 lock (`try_file_lock(<store>/session.lock)`) held for code.turn, code.compact, code.undo{confirm:true} → busy → error "Another aihub-code session is working in this project."; (d) code.undo result adds "skipped" (R17) and CheckpointError → error with its message (R15/R22); (e) code.start/resume while a code.turn is running → error "a turn is running" (set_session_dir is global) — cost if wrong: none.
- Ruling R31: no prefix suggestions for executor programs (find, sed, awk/gawk/mawk, tar, rsync, ssh, scp, xargs, parallel, watch, timeout, nice, nohup, git -c …) — exact command only; is_dangerous also flags find -exec/-execdir/-ok/-okdir/-delete/-fprint*/-fls, sed -i/--in-place and sed scripts with e/w commands, tar -x/--extract/-C/--directory/--to-command/--checkpoint-action, so they ask even with a prefix rule — cost if wrong: more prompts for find/sed.
- Ruling R27: record_before keeps a pre-turn copy for every tool-written path in shadow mode too; undo restores recorded paths the shadow doesn't track (ignored/excluded) from that copy with the usual end-fingerprint conflict check; anything still unhandled → skipped — cost if wrong: small extra copies per turn.
- Ruling R28: concurrent user edits — when a turn ran NO shell command, undo restores only tool-recorded paths; other paths changed start→end become conflicts (force to include). When shell ran, keep start→end. — cost if wrong: a model-free change during a shell-less turn needs force.
- Ruling R29: CheckpointStore re-reads and merges state.json from disk (under its file lock) in begin_turn, undo_plan and undo — fixes cross-process staleness — cost if wrong: one small JSON read per call.
- Ruling R30: compaction is cancellable (make_completer takes cancel_check; stops between chunks/stream parts, closes the stream, falls back deterministically); chat.py re-checks cancel right after before_round. Shell keeps a live-Popen registry with kill_all(), called from bridge main's finally and headless SIGTERM/SIGHUP handlers.
- Ruling R32: permission_request carries "permission_id"; chat.permission may echo it — an answer whose id doesn't match the pending request is dropped (answers without an id still accepted for the full-screen app) — cost if wrong: none.
- Ruling R33: prefix rules never apply to executor programs (find, sed, awk…, tar, rsync, ssh, scp, xargs, …): rule_matches requires an exact-command rule for them — closes every parser bypass in build mode structurally; is_dangerous stays a heuristic for auto (auto isn't a sandbox, spec) — cost if wrong: users re-approve each distinct find/sed command.
- Ruling R34: when the turn's start→end diff changes any .gitignore (or the repo's info/exclude content), undo never deletes "A" paths: those go to conflicts (force deletes; a recorded R27 pre-turn copy is restored instead of deleting) — cost if wrong: a file the agent created while editing .gitignore needs force to remove.
- Ruling R35: R29 merge ORs the `undone` flag (an undo in any process wins unless this process re-began that key); R32: pop the pending id in _dispatch when an answer is accepted, and an id-bearing answer (incl. null) with nothing pending is dropped.

## Known limits after the final round
- R33: every distinct find/sed/tar/awk/xargs/timeout command needs its own approval in build mode; saved prefix rules for them stop matching silently (interactive UI should say why).
- is_dangerous is a heuristic for auto mode (auto is not a sandbox).
- MCP tool file writes aren't recorded for undo; in a shell-less turn undoing them needs force.
- R27 keeps a pre-turn copy of every tool-written file per turn (pruned with the turn).
- Not verified on Windows/macOS (VM off): taskkill, msvcrt locks, PowerShell rule matching, kill_all on bridge exit.
- Interactive UI: echo permission_id in the code UI; answers without an id are still accepted.
